# Vela part-file manifest — THE build order and the routing table.
#
# One `part-<name>.jsx  # purpose` per line, in CONCAT ORDER. This file is the
# single source of truth for the part list: tools/vela-dev/scripts/concat.py
# (build), tools/vela-dev/scripts/lint.py (static checks) and tests/test_vela.py
# all read it — none of them keeps its own copy.
#
# ORDER IS LOAD-BEARING. The monolith is a plain concatenation with no module
# system, so every `const`/`let` is in one shared temporal dead zone: a part may
# only reference top-level bindings declared in an EARLIER part (or inside a
# function body that runs after mount). Reordering these lines reorders the
# bundle and can break the app at runtime with a TDZ ReferenceError. Do not
# reorder; append new parts at the position their dependencies require.
#
# Adding a part-file? Add it here in the same change — lint.py errors on any
# src/parts/part-*.jsx that is missing from this manifest.
#
# Lines starting with `#` and blank lines are ignored; text after `#` on a part
# line is the purpose comment.

part-imports.jsx  # VELA_VERSION/VELA_CHANGELOG, deck ingress + every sanitizer (validateAndSanitizeDeck, sanitizeSlide/Block, SAFE_SLIDE_KEYS/SAFE_BLOCK_KEYS, cssColor/cssGradient/cssUrl, sanitizeSvgMarkup, sanitizeImageDataUri), storage API (saveKV/MASTER_KEY), startup-patch system, themes/T tokens, cost tracker, shared prompt constants
part-icons.jsx    # Lucide icon resolver — resolveIcon/getIcon/IconSlot, ICON_ALIASES, ICON_EMOJI, lazy ensureIcons loader
part-blocks.jsx   # the 27 block renderers (RenderBlock's switch on block.type), SlideContent (slide background + block layout), BrandingOverlay (accent bar, footer, slide number, logo), renderBlockItem (per-block hover toolbar + AI prompt), EditableText/ItemChrome inline editing
part-reducer.jsx  # innerReducer action switch, undo/redo history wrapper (reducer, NO_HISTORY, MAX_HISTORY), initial state shape
part-engine.jsx   # Vera AI engine — callClaudeAPI, executeTool (tool switch), the system prompts that declare the tool contract, teacher mode, slide-design/timing APIs, ReAct loop
part-slides.jsx   # SlidePanel (editor slide view + keyboard/wheel nav), VirtualSlide, BrandingPanel, fullscreen/presenter (PresenterView, Presenter TOC, Gallery), StudentPanel, per-slide AI actions (runBlockEdit, quick edit, alternatives)
part-list.jsx     # lane/module/slide list (TOC): ModuleList → ConceptRow → SlideListWithAdder, ContextMenu/AddMenu, AiSlideAdder, drag-and-drop handlers
part-chat.jsx     # ChatPanel, ChatMarkdown, ToolTraceCard + TOOL_META, JSON clipboard modal
part-test.jsx     # dev-only battery render tests (excluded from --release builds)
part-uitest.jsx   # dev-only in-app UI test battery — uiSuite registry, runUITests, window.__velaRunUITests (excluded from --release builds)
part-demo.jsx     # cinematic demo mode — scripted scenes over the live app
part-pdf-fonts.jsx # COMPRESSED_FONTS — offline font fallback data (compressed TTF blobs), rarely changes; declared before part-pdf.jsx's loadFonts() reads it
part-pdf.jsx      # exporters: vector PDF (buildVectorPdf + DOM extractors + font parsing), canvas PDF (PdfExportModal), markdown (deckToMarkdown, mdInline/mdCell), standalone HTML — plus pdfStringEncode
part-pptx.jsx     # native editable PowerPoint export — buildPptx (OOXML+ZIP writer), pptxExtractTextBoxes, pptxEsc; reuses part-pdf.jsx extractors
part-app.jsx      # root VelaApp: top-level layout, storage load/save effects, deck import/export, global keyboard handlers, modals (ShortcutHelp, NewDeckDialog, StatsDialog, ChangelogDialog, PptxExportModal, MergePatchDialog), local/desktop sync
