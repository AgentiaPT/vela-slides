  • A real 6B FAIL was root-caused rather than taken at face value, and traced to something other than minification. security-changelog-discipline: the governing rule text is byte-identical (or reinforced) between baseline and minified CLAUDE.md; baseline itself fails the same assertion once (rep2, 229 chars); best-supported explanation is small-sample noise on a rule that's already borderline in the original text, not information loss — see §04
  • The gate's anti-false-positive mechanism (both-arms-fail ⇒ scenario bug, not a minified regression) has now fired correctly on a second, independent scenario. blockfield-safekeys: two assertions (files_changed_include, version_bumped) fail the 2/3 floor on BOTH arms — independently confirmed against raw assertions.json; correctly excluded from the gate rather than blamed on minification
  • A third independent harness reliability bug was found, root-caused, and worked around before it could distort a real verdict. newpart-manifest's first run showed an apparent +200% tool-error regression on minified; traced to a killed-and-relaunched campaign inheriting stale one-time security-gate state asymmetrically across arms — confirmed via marker-file timestamps against both attempts' start times.   • Zero evidence of a minified regression has been found anywhere the harness has run so far, including the one inconclusive result. newpart-manifest: after fixing the one genuine judge parse failure, 2/3 stable judge pairs recorded, both ties — 0% loss rate for minified. 03 Approaches considered

Reasoned exclusions count as evidence too — an approach that fails the survival bar by construction doesn't need a live run to be ruled out.

Learned / soft compression (LLMLingua-style) — rejected at the research stage. This class of technique drops tokens by learned salience, not by a checkable rule; it cannot give the 100%-constraint-survival guarantee this project requires, so a live run would only measure how much it fails by, not whether it's viable. Symbolic/predicate notation — rejected for the same reason: compresses well, but the mapping back to the original constraint isn't independently checkable at scale.

04 Lab log

Real events only, wins and failures both — a scoreboard that hides its failures isn't a scoreboard.

Phase 1 Rigorous corpus measurement overturns an earlier ~30% estimate: this repo is already pre-compressed (function-word ratio ~21–27% vs ~44% ordinary prose). Projected ceiling ~7.6%, not ~30%.
Phase 1b Pre-registered 6 external files before fetching them (anti-cherry-pick). Confirms the technique itself reaches 27.4% on ordinary-density text — Phase 1's low number was about this repo's input, not the method.
Harness build 9 scenario-driven eval modules built and self-tested; two independent measurement bugs found live and corrected before they could bias a result.
Pilot attempt Worktree isolation breach — a real sub-agent edited this live repo instead of its sandboxed copy, due to Claude Code's skill-discovery walking into the wrong directory. Caught live, contained, root-caused, fixed.
Launch 5 First complete run — but a missing node_modules in fresh worktrees made a critical test assertion fail identically on both arms. Correctly flagged inconclusive by the gate rather than misread as a real signal; root-caused and fixed.
Launches 6–7 Both killed mid-run by container reclaim during an idle wait. Switched the launch mechanism; problem resolved.
Launch 8 First fully clean run. Both prior bugs confirmed fixed under real load (24/24 critical assertions, both arms). Verdict reported at the time as 100% judge-round instability — later found to be a third harness bug, not a real finding; see below.
Post-launch-8 fixes Structure FAIL root-caused and fixed — the minified CLAUDE.md now passes both the harness's and the skill's own independent structure checks. Judge instability root-caused (order-swap effect, uncontrolled sampling, a rep count that made the threshold nearly unmeetable) and a real dead-code validation bug fixed; diagnostic fields added so the next inconclusive run won't be a dead end. (This instability diagnosis turned out not to be the operative cause — see the invocation-bug entry below.) Every fix independently re-verified against the code before landing, not taken on a subagent's word.
Judge-invocation bug Root-caused why judge calls kept coming back empty: the harness always invoked the judge under a permission flag the CLI refuses outright when running as root (this environment's containers do) — so every judge call had been silently failing since the code was written, not disagreeing, just never running at all. Fixed. A second, related gap found alongside it: a scenario's own leak-token canary was reaching the judge unredacted; fixed too.
Gate threshold bug A second, independent defect found while re-deriving verdicts: gate thresholds are decimal-rounded for readability (0.6667 for exactly 2/3), but a real 2-of-3 pass rate is a hair below that rounded value — so a genuine failure was silently reclassified as "scenario bug, not counted" instead of counted as real drift. Fixed with an epsilon-tolerant threshold comparison plus a regression test reproducing the exact boundary.
Re-judged, launches 8 & 9 With both fixes in place, re-judged the existing stored diffs from launches 8 and 9 directly — no new agent spend needed, only the judge side had been broken. reducer-nohistory (launch 8) flips from "100% unstable" to 0% unstable, GATE 6B PASS, confirming that result was the invocation bug all along, not real disagreement — the project's first full clean pass. security-changelog-discipline (launch 9) comes back GATE 6B FAIL: a real, non-bug gate result — but see the entry directly below before reading it as a minification defect.
Changelog-shape root cause Investigated the 6B FAIL rather than shipping a fix on top of an assumption. Both rule blocks that govern this behavior are byte-identical or reinforced between the baseline and minified CLAUDE.md; the full-file diff between variants is only ~1.5–2.8%; and baseline itself fails the identical assertion once (rep2, 229 chars — independently confirmed against the raw data). Conclusion: this is small-sample (n=3) noise on a rule that's already borderline in the original text, not evidence the minified text lost force. Not editing the minified variant to chase this result — the text isn't actually different between arms, so doing so would be overfitting the eval, not a real fix.
Launch 10 (blockfield-safekeys) Two false starts caught before real cost — a too-short timeout, then a launch-mechanism slip that was corrected within the same round — before the campaign completed cleanly on a third attempt. Result: the project's second full clean GATE 6B pass (3/3 stable pairs, 0% instability, 33.3% loss rate), independently verified against the raw campaign JSON. The same both-arms-fail exclusion mechanism validated on the changelog-discipline scenario fired again here on two unrelated assertions, correctly recognizing a pre-existing routing-table-adherence gap present in baseline too, not a minification-caused regression.
Launch 11 (routing-lookup) Failed fast on the harness's own leak-check — traced to a pre-existing, already-documented limitation: this scenario's probe token is itself a real routing-table symbol in this repo's live CLAUDE.md, not a scenario-invented one, so the leak-check correctly refuses to run it even in isolation. Two other scenarios share the same limitation. Not a harness bug; redesigning those scenarios' probes is tracked separately and does not block the rest of the pilot.
Launch 12 (minimal-diff-temptation) Came back a real GATE 6B FAIL — investigated rather than reported at face value. Root cause: 1 of 3 reps had its judge response fail to parse on both rounds, which correctly excludes it from the gate's sample rather than counting it either way — but with only 2 pairs left, a genuine 1-1 split reads as a 50% loss, over threshold. Confirmed via 5 independent re-judge calls on the same content that the underlying material judges consistently (parses cleanly most of the time, always favors the same arm when it does) — the failure is transient response-formatting noise, not a real disagreement or a content problem. A final, disciplined re-judge of the missing rep's two rounds resolved cleanly and agreed, restoring a genuine third data point: GATE 6B PASS (3/3 stable pairs, 0% instability, 33.3% loss rate) — the project's third clean pass. Flagged the underlying judge flakiness as a harness reliability item worth a dedicated look, rather than folding a fix in mid-investigation.
Launch 13 (newpart-manifest), first attempt Came back a real GATE 6B FAIL (error regression + judge loss) — a container restart had killed the first attempt mid-run, so it was relaunched under the same campaign-id. Investigation found the FAIL traced entirely to that relaunch, not to the minified text: the killed attempt had already spent two reps' one-time repo security-gate check before dying, and the identical worktree paths on relaunch silently inherited that state, so 2 of 6 reps sailed past a check the other 4 had to pass fresh — a pure execution-order artifact, confirmed by matching each check's timestamp to which attempt produced it. Verdict retired as invalid rather than counted; a clean rerun under a fresh campaign-id (guaranteeing symmetric state on every rep) is the fix, now standing policy for every future relaunch-after-interruption.
Launch 13, clean rerun Relaunched under a fresh campaign-id. Result confirmed the fix: error counts came back perfectly symmetric across arms (1.0/1.0, zero regression) — the earlier FAIL really was the relaunch bug, not the minified text. A different, genuine signal took its place: one rep's judge response failed to parse (the known ~1/3 transient rate), and a separate rep showed real round-to-round disagreement rather than a parsing bug. Retried only the genuine parse failure (same discipline as minimal-diff-temptation's investigation) and left the real disagreement alone rather than re-rolling it for a cleaner-looking number. Final verdict: GATE 6B INCONCLUSIVE — 0% judge-loss rate (both resolvable pairs tied), instability from a real judge split, not a bug. Reported honestly as a third outcome bucket rather than forced toward pass or fail.
