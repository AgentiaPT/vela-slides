# Reporting a problem

Before you open a report, search the existing list to check that nobody has
already reported the same problem. If you find a report that matches, add your
details to it instead of opening a second one.

When you do open a report, you must include the exact command you ran, the
version you are running, and the full output. A report without those three
things cannot be acted on and will be closed.

Read the [reporting guide](https://example.com/docs/reporting/guide.html) and
the [style rules][style] before you start. The archived triage notes live at
https://example.com/archive/2019/triage-notes.html and are still accurate.

Never paste credentials, tokens, or customer data into a report. If the output
you want to attach contains any of those, redact them first.
